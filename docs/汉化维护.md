# Dusklight 汉化版维护指南

本仓库（`loeissu/dusklight`）是官方项目 [TwilitRealm/dusklight](https://github.com/TwilitRealm/dusklight) 的中文汉化分支：

- `main` 分支：汉化后的完整源码 + 汉化 CI（Windows / Linux / Android）
- `tools/zh_cn.json`：英→中对照词典（翻译层，约 670 条）
- `tools/apply-zh.py`：把词典应用到上游英文源码，重新生成汉化文件
- `tools/extract-zh.py`：从“英文版 / 汉化版”差异中提取/更新词典
- `tools/set-version.py`：同步时自动更新汉化版版本号（与上游正式版一致）
- `tools/zh-last-release.txt`：记录上次同步的上游正式版标签
- `android-keystore/release.keystore`：固定签名密钥（所有构建共用，保证可覆盖安装）
- `platforms/android/app/build.gradle`：自动从版本号推导 Android versionCode
- `res/rml/window.rcss`：手机窄屏适配（设置窗口上下堆叠、说明文字整行显示、弹窗可滚动）
- `src/dusk/ui/input.cpp`：手机触摸拖拽滚动（说明内容过长时可滑动查看全文）
- `src/dusk/ui/pane.cpp`：详情/说明面板每 15 个中文字自动换行，保证长说明完整显示
- `.github/workflows/sync-upstream.yml`：自动同步上游正式版 + 重新生成汉化 + 触发编译

## 如何跟进上游更新

### 自动同步（推荐）

仓库已配置每天 UTC 02:00 检查一次上游。**只有上游发布新的正式版
（GitHub Release，非预发布）时才会同步并触发三平台编译**；上游的普通
每日提交不会触发重新构建。也可以到 GitHub 仓库的
**Actions → 同步上游正式版并重新生成汉化 → Run workflow** 手动检查。

同步流程：

1. 查询上游最新正式版标签（`releases/latest`）
2. 与 `tools/zh-last-release.txt` 记录的版本比较，无新版则跳过
3. 把源码重置到新正式版标签，用 `zh_cn.json` 词典重新生成汉化
4. 自动更新 `CMakePresets.json` 中的版本号（`tools/set-version.py`）
5. 推送到本仓库 `main`，自动触发 build.yml 编译三个平台的汉化版

如果上游新增了词典里没有的界面文案，这些文案会保持英文（不会破坏编译），
在 Actions 的同步日志中会看到 `[missed ...]` 提示，按下面的方法补翻译即可。

### 手动同步

```sh
git remote add upstream https://github.com/TwilitRealm/dusklight.git
git fetch upstream --tags --force
# 假设要同步到 v1.4.2（以实际最新正式版为准）：
git checkout -B main v1.4.2
# 恢复本仓库特有文件（见 sync-upstream.yml 中的列表）
python3 tools/apply-zh.py
python3 tools/set-version.py 1.4.2
echo "v1.4.2" > tools/zh-last-release.txt
git add -A && git commit -m "sync: 同步上游并重新生成汉化"
git push origin main
```

## 上游更新后如何补翻译

1. 同步后编译新版，界面上出现英文的字符串就是需要补翻译的
2. 直接修改源码中对应文件的英文字符串为中文（保持 `{}` 占位符不变）
3. 更新词典：

```sh
python3 tools/extract-zh.py --base 82e2fd4bea
```

   其中 `--base` 传上游基准提交号；也可以对比任意两个版本：

```sh
python3 tools/extract-zh.py --base <上游提交> --translated <汉化提交>
```

4. 提交 `tools/zh_cn.json` 和源码改动，推送到 `main` 即可触发重新编译

## 检查有哪些英文没翻译

```sh
python3 tools/apply-zh.py --check
```

会列出词典中未能匹配到的英文条目（通常是上游改过、需要更新的翻译）。

## 下载成品与 Android 签名

- 构建产物在 GitHub 仓库 **Actions → Build → 对应运行记录 → Artifacts** 页面下载
- 产物名：`Dusklight-汉化版-win32-x86_64`、`Dusklight-汉化版-linux-x86_64`、`Dusklight-汉化版-android-arm64`
- Android 签名密钥已固定保存在仓库 `android-keystore/release.keystore`
  （密码 `dusklight-zh-2026`），所有构建共用同一证书；APK 的 versionCode 会随版本号
  自动递增（如 1.4.1 → 10401、1.4.2 → 10402）。因此**汉化版新版本可以直接覆盖安装
  旧版汉化版，不需要卸载**，存档也能保留
- 如果想改用自己保管的密钥：把 `release.keystore` 用 base64 编码后配置为 GitHub 仓库
  Secret `ANDROID_KEYSTORE_B64`（密码不变），构建会优先使用该 Secret
- 注意：官方原版（Twilit Realm 签名的 APK）与汉化版签名不同，**从官方版切换到汉化版
  仍然需要先卸载官方版**（这是 Android 签名机制决定的，无法绕过）

## 手机界面说明文字被截断

已在 `res/rml/window.rcss` 中加入窄屏适配：手机竖屏时设置窗口改为上下堆叠，
说明文字占满整行显示、字号略降、弹窗内容可滚动。如果之后发现仍有说明显示不全，
可以在该文件的 `@media (max-width: 720dp)` 块里继续调整字号与内边距。

另外在 `src/dusk/ui/input.cpp` 中实现了手机触摸拖拽滚动：在说明区域按住上下滑动
即可查看全文。该实现会先判断 RmlUi 自带的触摸滚动是否生效，生效则跟随、不生效才
由应用层直接滚动，因此不会出现双重滚动。

`src/dusk/ui/pane.cpp` 中为详情/说明面板增加了“每 15 个中文字强制换行”：
只作用于说明面板，自动跳过 HTML 标签与实体，不依赖屏幕宽度判断，手机和 PC 都生效。

## 汉化范围

已汉化：启动器/预启动界面、设置、菜单栏、模组管理、日志、按键配置、手柄/触屏、
成就、传送、图形调节、崩溃上报、预设选择、调试编辑器（道具/黄金虫/信件/传送点）、
地图与区域名称、模组加载错误提示、Android 应用名。

保留英文：物理手柄按键名（Start/Select 等）、图形后端名称（Vulkan/D3D12 等）、
游戏内剧情文本（来自光盘镜像，不属于本仓库）。
